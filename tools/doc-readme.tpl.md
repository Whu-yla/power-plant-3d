## 1 项目简介与文件结构

### 1.1 项目定位

本项目把《某电厂总平面规划图（总平面布置图）》DWG 中的二维总平面信息，转换为可在浏览器中离线浏览的三维厂区模型，用于：

- 厂区空间关系与总体布置的直观核对（主厂房—冷却塔—煤场—升压站—施工临建的相对位置与间距）；
- 方案汇报与三维演示，无需安装 CAD；
- 作为 Hermes 运维后台的三维底板，通过 `postMessage` 接受聚焦、告警、状态等联动指令，并为巡检点位、设备状态、管线廊道预留扩展位。

模型为**示意级（方案级）几何**：平面位置与主要轮廓来自图纸实体解析，体量与高度多数为常规工程估算（见第 5 节），不用于施工放样。

### 1.2 文件结构

{{FILE_TABLE}}

`vendor/` 目录是离线运行的关键：Three.js 以 **r13x UMD 构建**（全局变量 `THREE`）本地引入，`OrbitControls.js` 同样为 UMD 版本，因此页面不使用 ES Module、不访问 CDN、不需要本地服务器，双击 `index.html`（`file://` 协议）即可打开。这样做的好处是现场笔记本、内网隔离环境、U 盘拷贝都能直接演示；代价是 `file://` 下的跨文档通信受限，接入 Hermes 后台时需改为 HTTP 方式部署（见第 8 节）。

`plant-data.js` 是唯一的数据源：采用 UMD 风格的立即执行函数，把 `PLANT_DATA` 挂到 `window` 上，既能在浏览器中直接 `<script>` 引入，也能被 Node 脚本加载做校验（本文档中的统计数字即由脚本从该文件读取后生成）。

> 说明：`index.html`、`style.css`、`builders.js`、`main.js` 由前端工程按同一套数据约定实现；本文档对其行为的描述依据项目设计约定（交互方式、开关、扩展钩子），具体实现细节以工程代码为准。

### 2.4 从实体到构件的数据流

```
DWG ──dump.mjs──▶ 实体集 ──labels.py──▶ 文字标注 ──an14/an17──▶ 编号点、圆弧圆心/半径
                     │                                        │
                     ├──raster.py/raster2.py──▶ 核对图 PNG     │
                     └──an19.py──▶ 道路四边形 quads.json ◀─────┘
                                        │
                                    mkdata.py
                                        ▼
                                  plant-data.js
```

关键约束：**坐标只在 `mkdata.py` 中换算一次**，进入 `plant-data.js` 的 `x/y` 一律是图纸测量坐标（东 E / 北 N），渲染层再统一减去 `meta.origin`。这样图纸坐标、世界坐标、截图核对的对应关系始终可回溯，不会出现"数据里改一次、渲染里再改一次"的累积偏移。

### 2.5 图纸一览表与建模覆盖情况

《二期工程建构筑物一览表》按编号 101–142 列出二期建构筑物（101 汽机房 … 142 #6 输煤转运站），共 142 项。本版模型覆盖其中 101–136 区间的 **30 个编号**（同一编号的 1#/2# 分列后共 41 个构件实例），另有 4 个一期既有设施（`code` 记为"一期"）与 26 个施工临建记录（`code` 为 S-01…S-26）。

需要如实说明的是：

- **115 渣库**：仅在一览表表格文字中出现，图面没有对应的轮廓或编号标注点，**未建模**；
- **136 卸煤槽**：一览表有条目，图面仅见铁路专用线，未见卸煤槽编号标注，按铁路线与输煤系统走向**推定了位置**后建模（`src` 中已注明），位置与尺寸均待复核；
- **137–142 输煤转运站**（#1–#6）：同样只在一览表文字中出现，图面未找到明确标注点，**未建模**；图面另有 #1–#5 输煤栈桥的文字标注，本版亦未建模（第 9.5 节给出扩展建议）。

一览表中其余未建模编号，本版未做定位，不属于"已确认无此设施"，而是"图纸信息不足，暂不进入模型"。复核时应结合施工图或现场踏勘补齐。

## 3 坐标系与比例标定

### 3.1 图纸坐标

图纸采用的是**测量坐标**（高斯平面直角坐标形式的东 E / 北 N），而非以图框左下角为原点的绘图坐标：

- 主图幅范围约 **E 2900900–2902800**、**N 2548300–2549700**，即约 1,900 m × 1,400 m；
- 厂区边界折线范围 E 2901130–2902420、N 2548500–2549565，围合面积约 **106.1 ha**，周长约 **4,260 m**；
- 构件坐标范围 E 2901247.9–2902414.5、N 2548688.3–2549542.1，与厂界基本吻合。

这类坐标的绝对值很大（百万级），直接放进 Three.js 会因浮点精度导致模型抖动、拾取失准。因此数据文件保留图纸坐标，渲染时统一减去 `meta.origin = (2900800, 2548300)`。

### 3.2 比例标定的证据链

图纸没有直接标注绘图比例，且 DWG 内部单位可能是毫米、米或无量纲，**必须标定"1 图纸单位等于多少米"**。标定过程如下，环环相扣：

**第一步：从几何实体反算真实尺寸。** 冷却塔在图中不是图块，而是用**两个顶点、bulge = 1 的 LWPOLYLINE 半圆**绘制的。bulge = 1 对应圆心角 180°（`tan(θ/4) = 1 → θ = 180°`），因此两个顶点就是直径的两个端点。反算得到：

| 项目 | 数值 |
|---|---|
| 1# 冷却塔圆心 | E 2901391.4，N 2549265.3 |
| 2# 冷却塔圆心 | E 2901541.1，N 2549374.0 |
| 外圈半径 / 直径 | 51 m / 102 m |
| 内圈半径 / 直径 | 40 m / 80 m（塔内环形基础轮廓，建模只取外圈） |
| 两塔圆心距 | 185.0 m（与图纸标注"两塔间距约 185 m"一致） |

**第二步：用一览表面积做量纲校验。** 若 1 图纸单位 = 1 m，则单塔占地面积 = π×51² = **16,342 m²**；图纸《二期工程建构筑物一览表》"127 循环水冷却塔"记 **16,400 m²**，相对误差 0.35%（差异来自按 51 m 取整、未计环形基础外挑）。吻合。

**第三步：排除其他量纲假设。** 若按 1 单位 = 1 mm 解释，冷却塔直径只有 0.102 m，面积 0.008 m²，与 16,400 m² 相差 6 个数量级；若按 1:1000 的打印比例反推，则需假定图纸被缩放，但测量坐标本身的米制量级（E/N 均在 2.9×10⁶ / 2.5×10⁶ 附近）表明坐标就是米。**因此判定：1 图纸单位 = 1 米，全图按米解释。**

**第四步：用独立构件交叉验证。** 标定结论在其他构件上同样成立：

| 构件 | 图面量测 | 一览表/常规值 | 偏差 |
|---|---|---|---|
| 制氢站 | 31.5 × 31.5 = 992 m² | 1,000 m² | +0.8% |
| 汽机房 | 175 × 34.4 = 6,020 m² | 6,020 m² | 0（尺寸按面积反算） |
| 烟囱 | 占地 210 m² → 底径 16.4 m | 210 m² | 0（按面积反算） |
| 冷却塔（两座） | 2 × 8,170 m² = 16,340 m² | 16,400 m² | +0.4% |
| 干灰库 | Ø17 m | 图纸文字 Ф15 m | 见第 11 节复核项 |

### 3.3 三维世界坐标约定

```
世界坐标 W = 图纸坐标 D − 原点 (2900800, 2548300)
             X = E − 2900800      （东向为正）
             Y = N − 2548300      （北向为正）
             Z = 高度（m），地面为 0
```

渲染到 Three.js 时，场景采用 **Z 轴向上**（`camera.up.set(0, 0, 1)`，须在创建 `OrbitControls` 之前设置），约定：

```
three.position = (E − 2900800, N − 2548300, 高度)   // x = 东，y = 北，z = 高
```

- 构件沿 X（东西）× Y（南北）铺开，Z 表示高度：`BoxGeometry(width, depth, height)` 对应"东西 × 南北 × 高"，构件中心位于 `z = h/2`；
- 相机默认在厂区南侧偏高处（y 的负方向一侧）向北看，屏幕上方为北，平面方位与 CAD 图一致；
- 若改用 Three.js 常规的 Y-up 写法 `(X, Z, −Y)`，等价于整场绕 X 轴旋转 90°，构件相对关系不变，但**巡检点位、管线、告警标记、GLB 导出等扩展代码必须与主场景保持同一约定**，混用会导致点位与高度错位。

举例（由数据直接换算）：

| 构件 | 图纸坐标 (E, N) | 世界坐标 (X, Y) | 高度 |
|---|---|---|---|
| 1# 冷却塔 | (2901391.4, 2549265.3) | (591.4, 965.3) | 130 m |
| 烟囱 | (2901752.8, 2549050.0) | (952.8, 750.0) | 210 m |
| 500 kV 配电装置 | (2901759.8, 2549379.5) | (959.8, 1079.5) | 26 m |
| 厂界西南角 | (2901130, 2548880) | (330, 580) | 0 |

### 3.4 精度与尺度说明

- 图形量测精度：实体坐标保留 0.1 m 量级，多次量测同一边的偏差 ≤ 0.5 m；构件外包矩形按实测轮廓取整到 0.1 m。
- 冷却塔圆心、半径由半圆端点反算，误差 < 0.2 m；半径取整为 51 m 后与一览表面积吻合度 0.35%。
- 图纸无量测高程（无等高线参与的建模），全厂按同一地坪（Z = 0）处理，竖向关系仅由建筑高度体现，**竖向设计、场地坡度、防洪标高不在本模型范围内**（列为复核项）。
- 模型单位：1 场景单位 = 1 m；构件尺寸与真实尺寸同量级，可直接量取距离、判断间距。

## 6 建模方法与几何约定

### 6.1 坐标与单位

- 场景单位 1 = 1 m；所有构件以"底面落地"为基准，盒体中心位于 `z = h/2`。
- 平面坐标换算：`three.position.set(x − origin.e, y − origin.n, h/2)`（Z 轴向上，约定见 3.3）。
- 拾取与信息面板依赖 `mesh.userData.id = 构件 id`，构建时逐个写入，便于 `raycaster` 反查数据。
- 材质按类别区分（主厂房浅灰、冷却塔混凝土灰、煤场深褐、电气构架银灰、施工临建半透明蓝灰、绿化绿），状态色由第 9.2 节覆盖。

### 6.2 双曲线冷却塔（`shape: hyperbolic`）

自然通风冷却塔的塔筒是旋转双曲面，用 `THREE.LatheGeometry` 最经济：

- 塔筒母线按双曲线方程 `r²/a² − (z−z0)²/b² = 1` 参数化：喉部半径 `a ≈ 0.5R`（塔底半径的一半），喉部标高 `z0 ≈ 0.8H`，由 `r(0) = R` 反算 `b`，沿高度取 26 个剖面点；底部保留约 8%H 的进风口敞开段，不封闭塔筒；
- 剖面点交给 `LatheGeometry` 车削（64 个旋转分段）生成旋转面，近景轮廓足够平滑；材质双面（`side: THREE.DoubleSide`），避免从塔口看穿；
- 塔内淋水装置、支柱、环形基础可用简化几何补充（低多边形即可，远景不可见）。

两塔按数据中的圆心分别放置，间距 185 m 由坐标自动保证，不做手工对位。

### 6.3 红白分段烟囱（`shape: chimney`）

- 单筒烟囱按 **30 m 一段分 7 段**（210 m，段数为 `ceil(H/30)`），自下而上半径由 8.2 m 线性收至约 55%（出口直径约 9 m），用 7 段圆柱体叠放，段间共用顶点高度以避免缝隙；
- 材质红白交替（航空标志漆），红色段与白色段各 3–4 段；
- 顶部可加航空障碍灯（小球 + 自发光材质，`setStatus` 时可闪烁），底部与烟道（ST-107）接口处用一段水平方管衔接。

### 6.4 建筑与场坪（`shape: box` / `pad` / `pit`）

- 建筑：底面 `w × d`、高 `h` 的拉伸盒体，位置 `(x − origin.e, y − origin.n, h/2)`；屋顶加 1.4 m 挑檐（女儿墙），层高 ≥ 12 m 时加三道窗带，大跨厂房（h ≥ 30 m 且宽 ≥ 100 m）加屋脊通风器；
- 场坪（`pad`，施工临建、停车场、堆场）：厚度取 `h`（通常 0.4 m）的扁平盒，直接落地，按类别取材质（土面 / 硬化 / 碎石），半透明以体现"临时设施"属性；
- 水池、油池（`pit`）：用"池壁围合 + 池底薄板"表达（壁厚约为短边的 5%，壁高 1.0–2.6 m），池底铺水面材质，竖向不做真实开挖，信息面板注明"地下/半地下"；
- 门式支架（`gantry`）：四角立柱（柱宽约为短边的 5%，最小 0.9 m）+ 4 道水平横梁 + 顶部平台 + 前后两面 X 形斜撑，顶部再放一个筒形设备体量（风机/设备）；
- 变压器（`transformer`）：箱体 + 顶部套管（细圆柱）+ 散热器片（薄板阵列），底部加混凝土基础台；
- 挡煤墙（`retaining`）：1 m 厚 × 120 m 长 × 3 m 高的薄墙。

### 6.5 构架式升压站（`shape: switchyard`）

500 kV 配电装置按"碎石场地 + 构架 + 设备基础 + 软母线"表达：

- 场地按 200 m × 131 m 铺一层碎石地坪；
- 纵向按约 32 m 柱距划分（200 m 场地上 6 跨），每跨两侧立柱 0.9 m × 0.9 m × 26 m，柱顶与 0.8H 处各设一道横梁，形成门型架；
- 软母线与纵向连梁用细圆柱（半径约 0.28 m）沿东西向拉通，分 3 道，模拟出线间隔；
- 隔离开关、断路器基础用简化方块（约 7 × 5 × 4.5 m）按间隔布置；
- 场外围栅（图纸标注周长约 690 m）属可选细节：本版未建模，如需表达可用半透明网格材质或线框，避免遮挡内部设备。

### 6.6 圆筒穹顶煤仓与贮煤场（`shape: dome` / `coalheap`）

- 圆形封闭煤仓：筒身直径 72 m、高约 0.58H（55 m 总高时约 32 m），上接椭圆母线车削的穹顶（0.58H → H，顶部收口约 1.1 m），总高 55 m 含穹顶；
- 条形煤场（`coalheap`）：按梯形断面（顶宽约为底宽 28%）沿长度方向挤出成煤堆，高 14 m，下垫 0.3 m 碎石垫层；干煤棚本体本版未建，仅以煤堆体量表达；
- 圆煤仓外的环形道路（图纸 R40）已由道路四边形覆盖；若需更精细的环带，可另加 `RingGeometry` 平铺。

### 6.7 道路、围墙、绿化

- 道路：每条记录是 4 个顶点的路面四边形（由 `an19.py` 把道路双线配对得到），用两个三角形拼成 `BufferGeometry`，抬高 0.08 m 并开 `polygonOffset` 防 Z 冲突；沥青深灰材质，主干道（宽 7–10 m）与支路（宽 3.5 m）可用不同灰度区分；
- 围墙/厂界：沿 `boundary` 的 18 个点闭合，用 2.5 m 高、0.4 m 厚的双层墙体（内外面 + 压顶）表达；厂界外的场地不做建模；
- 绿化：以 `trees` 的 192 个点位生成 `InstancedMesh`（锥形树冠 + 圆柱树干两套实例），按点位随机微调尺度与朝向，避免机械重复。

### 6.8 标注与拾取

- 标注：构件顶点上方以 `Sprite`（Canvas 贴图）显示编号（`code`），材质关闭 `depthTest` 使其始终可见；标注可整体开关，名称与尺寸在信息面板中查看，不在场景内铺满文字；
- 拾取：`Raycaster` 命中后由 `mesh.userData.structId` 反查构件，填充信息面板（名称/编号/尺寸/面积/备注/数据来源），并以自发光（emissive）高亮选中与悬停状态。

### 7.4 浏览器兼容性

- 需要支持 WebGL 2.0 的现代浏览器（Chrome / Edge 90+、Firefox 90+）；
- 双击 `file://` 打开时，部分浏览器对本地文件的 `XHR/fetch` 有限制，因此页面**不加载任何外部文件**（纹理改用程序化材质或内联色块），保证离线可用；
- 集显笔记本（如 Intel UHD）在 71 个构件 + 192 个实例化树 + 140 段道路的规模下可稳定 30 fps 以上；若帧率不足，优先关闭阴影、降低 `LatheGeometry` 分段数与树木实例数。

## 8 Hermes 运维后台集成

### 8.1 部署方式

三维页面有两种打开方式：

1. **单机演示**：直接双击 `index.html`（`file://`），无需服务器；
2. **后台集成**：把整个目录作为静态资源放到 Hermes（8090 端口）服务的站点目录下（例如 `static/plant3d/`），通过 URL 访问，再用 `iframe` 嵌入运维后台页面。

集成时**不能**用 `file://` 作为 iframe 源：现代浏览器禁止 http(s) 页面加载本地文件子框架（控制台报 "Not allowed to load local resource"），且 `file://` 文档的源为不透明源（opaque origin），`postMessage` 的 `targetOrigin` 只能写 `*`，安全性与可维护性都差。因此集成场景统一走 HTTP。

```html
<!-- Hermes 后台页面中嵌入三维总平面 -->
<iframe
  id="plant3d"
  src="/plant3d/index.html?embed=1"
  title="三维总平面"
  style="width:100%;height:720px;border:0;border-radius:8px"
  allowfullscreen
  referrerpolicy="no-referrer">
</iframe>
```

`?embed=1` 为约定参数：进入嵌入模式后隐藏页面标题栏与帮助浮层，只保留画布与必要工具栏，便于后台布局。

### 8.2 postMessage 协议

父页面（Hermes，8090）→ 三维页面：

| 消息类型 | 载荷 | 含义 |
|---|---|---|
| `plant:focus` | `{ type:'plant:focus', id:'ST-108' }` | 相机飞行并聚焦到指定构件（若构件被隐藏会先自动显示） |
| `plant:alarm` | `{ type:'plant:alarm', id:'ST-127A', level:2 }` | 构件告警变色（红），`level` 1 = 仅变色、≥2 = 闪烁（当前实现把 2 与 3 同样处理，3 预留给更强烈的表现） |
| `plant:status` | `{ type:'plant:status', id:'ST-126', status:'alarm' }` | 统一的状态入口，`status ∈ normal / warning / alarm / offline`；`alarm` 自动闪烁 |
| `plant:visible` | `{ type:'plant:visible', id:'ST-S-25', visible:false }` | 控制单个构件显隐（`visible` 缺省视为 `true`） |
| `plant:inspect` | `{ type:'plant:inspect', point:{ id, name, x, y, z, status } }` | 新增巡检点位，`point` 也可直接平铺在消息上 |

三维页面 → 父页面：

| 消息类型 | 载荷 | 含义 |
|---|---|---|
| `plant:selected` | `{ type:'plant:selected', id:'ST-119', name:'500kV配电装置' }` | 用户点击选中构件时回发，父页面可据此同步高亮设备台账行 |

> 当前版本未实现 `plant:ready` 就绪握手，父页面需在 `iframe` 的 `load` 事件之后再下发指令；如需严格的时序保障，建议在三维页面初始化完成后增加一条 `plant:ready` 消息（一行 `postToHost({type:'plant:ready'})` 即可），父页面用 `message` 监听替代 `load` 事件。

父页面示例：

```js
const frame = document.getElementById('plant3d');

// 1) 监听三维页面回发的选中事件
window.addEventListener('message', (e) => {
  if (e.origin !== location.origin) return;          // 生产环境按源白名单校验
  const d = e.data || {};
  if (d.type === 'plant:selected') {
    highlightRow(d.id);                              // 后台台账联动
  }
});

// 2) iframe 加载完成后下发指令（当前版本无 ready 握手，先等 load）
frame.addEventListener('load', () => {
  frame.contentWindow.postMessage({ type: 'plant:focus', id: 'ST-108' }, location.origin);
  frame.contentWindow.postMessage({ type: 'plant:status', id: 'ST-127A', status: 'warning' }, location.origin);
  frame.contentWindow.postMessage({ type: 'plant:visible', id: 'ST-S-25', visible: false }, location.origin);
});

// 3) 同源 iframe 也可直接调用全局钩子（跨源时只能用 postMessage）
frame.contentWindow.PlantApp?.setAlarm('ST-127A', 3);
```

实现要点：

- 三维页面的消息监听会接受对象或 JSON 字符串，按 `type` 前缀分发；未知 `type` 静默丢弃；
- 回发消息使用固定的 `targetOrigin = 'http://127.0.0.1:8090'`（代码常量 `HOST_ORIGIN`）；三维页面部署在别的端口/域名时需同步修改，否则父页面收不到消息；
- 三维页面当前**不校验** `ev.origin`（便于 `file://` 本地调试，此时源为 `null`）；一旦以 HTTP 方式嵌入生产后台，应在监听器开头加白名单校验（如 `if (ev.origin !== 'http://127.0.0.1:8090') return;`）；
- 告警闪烁应在渲染循环中按时间插值材质颜色，不要每条消息都重建材质或场景；
- 高频指令（如大量设备状态刷新）建议在父页面合并后再下发，避免消息风暴。

### 8.3 安全与 CSP 注意事项

- 若 Hermes 页面设置了 CSP，需要允许同源子框架：`frame-src 'self';`（或把三维站点域名加入白名单）；
- 三维页面自身不引用任何外部资源（Three.js、OrbitControls 均为本地 vendor），因此**不需要**为它放开 `script-src` 的 CDN 例外；
- 若希望限制被第三方站点嵌入，可在三维页面响应头加 `Content-Security-Policy: frame-ancestors 'self'`（需由 8090 服务的静态资源响应头统一设置，`file://` 打开时该头不生效）；
- 生产环境建议只读展示：不开放文件写入、不上传数据，巡检点位与状态全部由后台下发。

## 9 扩展钩子与二次开发

### 9.1 全局 API

三维页面把对外能力挂在 `window.PlantApp` 上：

| 成员 | 参数 | 作用 |
|---|---|---|
| `focusOn(id)` | 构件 id，如 `'ST-108'` | 相机飞行并聚焦到该构件，同时高亮（隐藏的构件会先自动显示） |
| `setVisible(id, bool)` | id、是否可见 | 单个构件显隐；也可用于批量（前端界面按 id 循环调用） |
| `setAlarm(id, level)` | id、`1`/`2`/`3` | 告警变色；`level ≥ 2` 闪烁，省略 `level` 时默认闪烁（2 与 3 当前处理相同，3 为预留档） |
| `setStatus(id, status)` | id、`'normal' / 'warning' / 'alarm' / 'offline'` | 统一的设备状态入口，内部映射到配色与动效（`alarm` 自动闪烁） |
| `addInspectionPoint(pt)` | `{ id, name, x, y, z, status }` | 新增巡检点位；`x/y` 为**世界坐标**（已减 `meta.origin`），`z` 为地面以上高度，单位 m |
| `select(id)` | 构件 id 或 `null` | 以程序方式选中/取消选中（与鼠标点击等效，同步信息面板） |
| `getSelected()` | — | 返回当前选中构件的 id（无选中为 `null`） |
| `resetView()` | — | 复位到初始相机视角 |
| `requestRender()` | — | 标记需要重绘（页面按需渲染，外部改场景后调用） |
| `postToHost(payload)` | 任意消息对象 | 主动向父页面发送消息（默认 `targetOrigin` 为 `HOST_ORIGIN`） |
| `onSelect` | 回调函数 `(info) => void` | 用户点击构件时回调，`info` 含 `id/name/code` 等 |
| `scene` / `camera` / `renderer` / `controls` | — | 主场景、相机、渲染器、控制器（供二次开发与 GLB 导出） |
| `structures` | — | 运行时构件表 `[{ id, data, group, materials, status, visible }]` |
| `data` / `version` | — | 原始 `PLANT_DATA` 与模型版本号 |

> 本版**未内置 GLB 导出**（项目约定不引入额外依赖）；需要导出时按 9.4 节自行挂载 `THREE.GLTFExporter`。

调用示例：

```js
// 聚焦烟囱
PlantApp.focusOn('ST-108');

// 冷却塔告警（1 级）
PlantApp.setAlarm('ST-127A', 1);

// 设备离线
PlantApp.setStatus('ST-126', 'offline');

// 监听选择事件
PlantApp.onSelect = (info) => console.log('选中', info.id, info.name);
```

### 9.2 状态与告警配色

| 状态 | 颜色 | 表现 |
|---|---|---|
| `normal` | 类别本色 | 恢复该构件的基础材质（缓存的 base 颜色/自发光） |
| `warning` | 琥珀 `#e0a13a` | 基础色向琥珀插值 70%，自发光 `#6b3f00`（强度 0.32），不闪烁 |
| `alarm` | 红 `#d2453c` | 材质替换为红色、自发光 `#8d1d17`（强度 0.55）；`setStatus('alarm')` 或 `setAlarm(id, ≥2)` 时闪烁（2/3 当前处理相同） |
| `offline` | 暗灰 | 基础色亮度乘 0.42、关闭自发光，呈"停机"观感 |

此外，选中构件加蓝色自发光 `#1b4f7d`（强度 0.62），鼠标悬停加 `#14405f`（强度 0.40），这些高亮在状态色之上叠加，状态切换后仍保留选择反馈。

实现建议：为每个构件缓存原始材质参数（页面内的 `baseOf`），状态切换时只改 `material.color / emissive / emissiveIntensity`，不重建几何；闪烁在渲染循环中按时间插值，避免 `setInterval` 堆积。

### 9.3 巡检点位

```js
// 图纸坐标 (2901391.4, 2549265.3) 先换算为世界坐标 (591.4, 965.3)
PlantApp.addInspectionPoint({
  id: 'PT-001',
  name: '1# 冷却塔塔顶巡检点',
  x: 591.4,           // 世界坐标 X = E − 2900800
  y: 965.3,           // 世界坐标 Y = N − 2548300
  z: 130,             // 地面以上高度 m
  status: 'normal'
});
```

点位由"立柱 + 发光球 + 地面光环 + 文字标签"组成，`status` 沿用 9.2 的配色；若手上是图纸测量坐标，必须先减去 `meta.origin` 再传入（函数内部不再做换算）。点位数据建议由后台按设备台账下发，避免写死在 `plant-data.js` 中；批量导入时可在 `addInspectionPoint` 外层循环，或仿照它实现 `addInspectionPoints(list)`。

### 9.4 GLB 导出方案

若需要把模型交给其他平台（如 UE、Unity、轻量化审查工具）使用，可用 Three.js 官方的 `GLTFExporter`：

```js
// vendor/ 下补充 GLTFExporter.js（r13x 的 examples/js/exporters 版本，UMD）
const exporter = new THREE.GLTFExporter();
exporter.parse(
  PlantApp.scene,
  (result) => {
    const blob = new Blob([JSON.stringify(result)], { type: 'model/gltf+json' });
    const a = document.createElement('a');
    a.href = URL.createObjectURL(blob);
    a.download = 'plant-3d.gltf';
    a.click();
  },
  { binary: true, onlyVisible: true, trs: false }
);
```

注意事项：

- 场景本身为 Z 轴向上，`GLTFExporter` 按 glTF 规范输出 **Y-up**（自动做轴系转换），单位为米；若目标平台要求 Z-up，导入后再绕 X 轴旋转 90° 即可；
- `InstancedMesh`（树木）在旧版导出器中可能不被支持，导出前可临时替换为普通 `Mesh`，或直接排除绿化层；
- 程序化材质（纯色、无贴图）导出后无贴图依赖，体积小；若后续加入贴图，需改为 `glb`（`binary: true`）并检查贴图内嵌；
- 导出文件建议按资产编号命名（`PP-3D-2026-001.glb`）并登记到归档清单。

### 9.5 管线、电缆廊道与输煤栈桥扩展

当前数据只有"占地矩形"（如 ST-128 循环水管）与场地轮廓，尚无三维管线。扩展建议：

1. 在 `PLANT_DATA` 中新增 `pipes` 数组，字段建议：`{ id, name, cat:'pipeline', path:[[E,N,Z],...], d, medium, src }`；
2. 构建：`CatmullRomCurve3` → `TubeGeometry(curve, 64, d/2, 8)`，按介质配色（循环水蓝、电缆灰、灰管深灰、蒸汽浅红）；

   - 循环水压力钢管：ST-126 循环水泵房 → ST-127A / ST-127B 冷却塔；

## 10 修改说明

### 10.1 修改坐标与尺寸

- **位置**：编辑 `plant-data.js` 中对应构件的 `x`（东 E）、`y`（北 N），**必须使用图纸测量坐标**，不要填世界坐标（`x − 2900800` 的值）。判断方法：`x` 应在 2901000–2902500、`y` 应在 2548400–2549600 区间内。
- **尺寸**：改 `w`（东西向宽）、`d`（南北向深；圆形构件为直径）、`h`（高度），同步改 `area`，保持 `area ≈ w × d`（圆形 `area ≈ π(d/2)²`）；若构件实际占地与外包矩形差异大（如栈桥、管线），可在 `note` 中说明，不要强行让 `area` 等于 `w×d`。
- **旋转**：本版 `rot` 全为 0，若某单体需斜置，改 `rot`（绕 Z 轴、逆时针为正）。构建器约定：绝对值 > 6.5 视为**度**（内部换算 `rot × π/180`），否则视为**弧度**——填 `15` 即 15°，填 `0.26` 即 0.26 rad，二者等效。
- **坐标系整体平移**：仅当测量坐标系本身变化时才改 `meta.origin`，改后全图一起平移；不要为了"让某个构件居中"而改 origin。

### 10.2 新增构件

1. 复制一个同类构件对象作为模板，分配新的 `id`（保持 `ST-` 前缀、全局唯一）；
2. `cat` 必须是 `main / cooling / coal / electrical / aux / living / construction` 之一，否则类别开关与配色会失效；
3. `shape` 复用已有类型（见 4.1）；若确需新类型，在 `builders.js` 中注册同名构建函数，返回 `THREE.Group` 或 `Mesh`，并把 `userData.id` 写进去；
4. 若新增构件属于图纸一览表编号，`code` 填对应编号，并在 `src` 中写清位置与尺寸依据；
5. 新增后建议跑一次数据校验（面积与外包矩形偏差、坐标是否落在厂界内），并同步更新本文第 4 节表格与归档统计。

### 10.3 替换为 GLB 外部模型

单体建筑若已有精细模型（如主厂房、冷却塔），可替换程序化几何：

```js
// 1) vendor/ 下补充 GLTFLoader.js（r13x UMD）
const loader = new THREE.GLTFLoader();
loader.load('models/turbine-hall.glb', (gltf) => {
  const obj = gltf.scene;
  // 2) 统一到米制、底面落地：按包围盒缩放到 w/d/h
  const box = new THREE.Box3().setFromObject(obj);
  const size = box.getSize(new THREE.Vector3());
  obj.scale.set(w / size.x, d / size.y, h / size.z);
  // 3) 重新计算包围盒后把底面中心对齐到世界坐标 (x − origin.e, y − origin.n, 0)
  const box2 = new THREE.Box3().setFromObject(obj);
  const c = box2.getCenter(new THREE.Vector3());
  obj.position.set(data.x - ORIGIN.e - c.x, data.y - ORIGIN.n - c.y, -box2.min.z);
  obj.userData = { id: data.id };
  scene.add(obj);
});
```

要点：外部模型进入场景前必须统一单位与朝向（GLB 为 Y-up、米制，读入 Z-up 场景要先 `obj.rotation.x = Math.PI / 2`；导出为厘米时再缩放 0.01）；用包围盒对齐而不是凭感觉调位置；保留 `userData.id` 以维持拾取与告警能力；加载失败要有降级（回退到程序化盒体），避免空白。

### 10.4 数据修改禁忌

- 不要手工重排 `roads` 中四边形的顶点顺序——顶点按"沿路方向"成对生成，顺序错乱会导致路面扭曲；
- 不要删除 `plant-data.js` 末尾的 UMD 包装（`(function (global) { ... })(window)`），Node 校验脚本与浏览器共用同一份文件；
- 不要手工编辑 `readme.md` 中的统计表而不改数据——本文档表格由脚本从 `plant-data.js` 生成，数字与数据文件同源；
- 修改后至少在浏览器里核对一次：构件是否落在正确位置、面积是否与一览表仍大体吻合、道路是否与建筑冲突。
